# BIRTHDAY QUEST: LOVE.EXE

## 실행

Node.js 18.20 이상에서 실행합니다. 향후에는 지원 중인 Node.js LTS 사용을 권장합니다.

```sh
npm install
npm run dev
npm run test
npm run build
npm run preview
```

개발 서버 기본 주소: http://localhost:5173

## 구조

- `src/pages/`: 인트로, 허브, 스테이지 라우팅, 잠금 조건이 있는 엔딩 및 404 화면
- `src/features/`: 여섯 개 스테이지의 독립적인 게임 컴포넌트
- `src/components/`: 레이아웃, 픽셀 캐릭터/아이콘, 스테이지 카드, EXP 바
- `src/data/stages.ts`: 스테이지 메타데이터와 타입
- `src/data/content.ts`: 장소, 객관식 퀴즈, 쿠폰, 커밋 콘텐츠
- `src/state/`: 진행 상태 검증, localStorage 저장, Context
- `src/styles.css`: 공통 색상, 픽셀 스타일, 반응형 및 접근성
- `src/quest-styles.css`: 스테이지 및 편지의 반응형 UI
- `tests/`: 진행 상태 검증 테스트

## 진행 상태

저장 키는 `birthday-quest:progress:v1`입니다. 최초 클리어 ID만 저장하고 EXP는 완료 개수로 계산합니다. 각 스테이지의 실제 완료 조건에서 `useProgress().clearStage(stageId)`를 호출합니다. 완료 후 다시 플레이해도 EXP는 증가하지 않습니다. 초기화는 브라우저 확인 창에서 승인했을 때만 진행됩니다. 잘못된 JSON은 초기 상태로 복원하고, 중복/알 수 없는 ID는 제거합니다. 저장 실패 시 안내합니다.

마지막 가챠 쿠폰은 `birthday-quest:coupon:v1`에 저장합니다. 게임 초기화는 진행 상황과 마지막 쿠폰을 지웁니다. 퀴즈 답변 및 장소의 부분 열람 상태는 해당 화면에 있는 동안만 유지됩니다. `/ending`으로 직접 진입해도 6개 퀘스트를 완료하기 전에는 편지를 보여주지 않습니다.

## 디자인과 배포

외부 이미지, 지도 API, 백엔드, 로그인, 배경음악을 사용하지 않습니다. 픽셀 캐릭터와 아이콘은 자체 SVG입니다. 무료 Google Fonts를 불러오며 네트워크가 없으면 시스템 글꼴을 사용합니다. 520px 이하에서는 카드가 한 열, 850px 이하에서는 두 열로 전환합니다.

Vercel 빌드 명령은 `npm run build`, 출력 디렉터리는 `dist`입니다. `vercel.json`의 SPA rewrite로 직접 진입/새로고침을 지원합니다. 현재 배포는 수행하지 않았습니다.

## 참고 문서

`프로젝트설정.docx` 및 `Birthday_Quest_Love_1.pdf`는 기획 참고용 원본입니다. PDF의 초기 기획은 7개 스테이지지만 최신 요청과 Word 문서에 따라 6개로 반영했습니다. 지도 사진 자동 수집과 지도 임베드는 미구현이며 지도 검색 링크로 대체했습니다.

## 검증

`npm run build`의 TypeScript 검사와 Vite 빌드, `npm test`의 4개 진행 상태 테스트를 통과했습니다. 브라우저 검수 도구가 제공되지 않아 390px/PC 화면의 실제 렌더링, 키보드 이동, 확인 창 및 브라우저 재시작 후 저장 복원은 아직 수동 검수가 필요합니다.

수동 확인: `/`에서 게임 시작 → `/hub`의 카드 6개 및 EXP 확인 → 각 스테이지의 목표 달성 → 최초 완료 EXP +1 확인 → 동일 스테이지 재시도 시 EXP가 그대로인지 확인 → 6/6에서 편지 열기 → 새로고침 및 브라우저 재시작 후 진행 복원 확인. `/ending` 직접 진입 시 6/6 미만이면 잠금 안내가 표시되어야 합니다.

모바일 390px와 PC 1280px에서 가로 스크롤이 없는지, Tab/방향키로 버튼 및 라디오 선택지에 접근 가능한지 확인합니다. 퀴즈 미선택 시 제출이 차단되어야 하고, 틀린 답을 제출해도 마지막 문항 이후 클리어되어야 합니다. 가챠 재추첨 시 마지막 쿠폰이 저장되어야 합니다. 초기화 취소는 진행과 쿠폰을 유지하고, 승인은 두 저장 데이터를 초기화해야 합니다.
